Collez ou éditez un tableau JSON d’objets créneau dans schedule_slots.

Préférez le JSON pour plus de six créneaux ou la duplication entre instances.

Le format est identique à celui produit par le formulaire.

Chaque créneau définit une plage horaire, un prix d’énergie (par kWh), les jours concernés et un libellé optionnel.

L’intégration enregistre les créneaux en JSON : un tableau d’objets dans schedule_slots (données de l’entrée de configuration Home Assistant).

Structure JSON — référence des champs

Champ Obligatoire Type Description
start oui chaîne Heure de début, HH:MM (24 h). Les secondes (HH:MM:SS) sont acceptées et normalisées en HH:MM.
end oui chaîne Heure de fin, même format. 00:00 signifie minuit en fin de journée (équivalent 24:00), pas minuit au début. À utiliser pour les plages qui passent minuit (ex. 22:00 → 00:00).
price oui nombre Prix de l’énergie, dans la devise configurée, par kWh (≥ 0).
day_type non chaîne L’une des valeurs : all, weekdays, weekends. Défaut : all.
name non chaîne Libellé court pour l’UI / les journaux (ex. Night, Peak).

Valeurs de day_type

  • all — tous les jours
  • weekdays — lundi à vendredi
  • weekends — samedi et dimanche

Exemple minimal (deux plages, tous les jours) 

[
  {
    "start": "22:00",
    "end": "06:00",
    "price": 0.1296,
    "day_type": "all",
    "name": "Off-peak"
  },
  {
    "start": "06:00",
    "end": "22:00",
    "price": 0.1609,
    "day_type": "all",
    "name": "Peak"
  }
]

    "start": "00:00",

Validation (résumé)

  • Au moins un créneau est requis.
  • Les heures doivent être valides en 24 h (HH:MM).
  • price doit être un nombre ≥ 0.
  • Si day_type est présent, il doit être exactement l’une des trois valeurs autorisées.

Le moteur tarifaire confronte l’heure locale et le jour de la semaine aux créneaux ;

le comportement en cas de chevauchement dépend de l’ordre et de l’évaluation dans le code — gardez une intention claire et évitez les recouvrements redondants lorsque c’est possible.
