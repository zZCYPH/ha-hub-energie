Hub Énergie

A Home Assistant custom integration for energy monitoring, cost tracking, and diagnostics. It supports generic supplier and tariff setups, multi-battery systems, optional solar PV estimation, and three-phase grids.

Home Assistant 2024.10.0+ Version 0.2.2 GitLab repository Issue tracker

Supported scope (v0.2.x)

Intended to be stable

  • Config flow: supplier (EDF vs custom), tariff model (flat, HP–HC, multi-slot, EDF Tempo with RTE, API, or sensor), grid and optional solar/battery wiring.
  • Energy accounting: positive deltas from total_increasing meters → internal slot-day accounting (Paris day) and integration-owned SSOT total sensors.
  • Costs: daily estimate (€) from rates + subscription split; per-slot breakdown in attributes.
  • EDF Tempo: colours, quotas, next-change timestamps when applicable.
  • Diagnostics: export / réinjection split, data quality, delta telemetry, unknown bucket and staleness; health sensor (ok / degraded / rebuilding / inconsistent / no_input) with a readable cause.
  • Optional clear-sky PV estimation and solar resale revenue when configured.
  • Lovelace card served from /hub_energie/ after build.

Experimental / best-effort

  • Power-flow–based battery charge origin split when sensors are partial or noisy.
  • Solar production estimation (model-based, not a physical meter).
  • Opportunity-cost diagnostics for exported kWh.

Data sources (SSOT)

  1. Physical meters (external SSOT) — Energy entities you configure (grid_import_energy, solar, export, per-battery in/out). Recorder history is ground truth for total kWh.
  2. Internal accounting — The coordinator accumulates positive deltas into totals and per-day slot kWh. Integration total_increasing SSOT sensors reflect this internal sum.
  3. Long-term per-slot kWh (daily) — External statistics (hub_energie:slot_<source>_<slot>_kwh) after each Paris day. Prefer these (or physical meters) for historical analytics—not raw cost_detail attribute history alone.

Installation

Install the repository contents exactly under:

<config>/custom_components/hub_energie/

Home Assistant must load custom_components/hub_energie/manifest.json — avoid a nested folder such as hub_energie/hub_energie/.

Ways to install

  1. HACS (custom repository): add the repo as an Integration, download so files land under custom_components/hub_energie/ (root layout via content_in_root in hacs.json). Restart HA, then add the integration under Settings → Devices & services. Build the Lovelace frontend if you use the card (npm ci and npm run build in frontend/).
  2. Git: clone into custom_components/hub_energie.
  3. Copy: copy the full tree (all subfolders), do not cherry-pick files.

After install: build the card if needed, perform a full Home Assistant restart, then add Hub Énergie from the integration UI. Match installs to the Git tag that matches manifest.json version for reproducibility.

Lovelace card

Vite outputs hub-energie-card-boot.js (shell, element hub-energie-card) and the full bundle under frontend/dist/. HA serves dist at /hub_energie/.

On startup the integration registers the boot URL as a JavaScript module. For YAML-managed resources, add:

resources:
  - url: /hub_energie/hub-energie-card-boot.js
    type: module

Replace legacy URLs (/hub_energie/dist/hub-energie-card.js, etc.) with the boot URL; avoid duplicate module entries for the same card.

type: custom:hub-energie-card

Configuration flow (summary)

  1. Supplier — EDF or custom
  2. Phase type — single or three-phase
  3. Tariff — auto (EDF) or manual (flat / TOU / schedule)
  4. Contract — power (kVA), name
  5. Grid sensors — import energy (required), export, power
  6. Solar — energy, power, resale, optional PV estimation
  7. Batteries — per-battery energy in/out, optional power / SOC / capacity

Services

Service Description
hub_energie.refresh Force coordinator refresh
hub_energie.refresh_tariffs Re-fetch EDF tariffs (auto mode)

Limitations (high level)

  • Recorder retention affects history, charts, and rebuild-from-recorder behaviour.
  • Optional solar estimation is clear-sky model output — indicative, not a production meter.
  • The card’s power graph depends on statistics; missing state_class or history can leave graphs empty.
  • Health states summarise many probes; brief rebuilding after recorder-based rebuild is normal.
  • See the repository’s docs/troubleshooting.md for trust states, unknown bucket, and recovery.

Measured, reconstructed, estimated

Measured From your configured HA entities (total_increasing kWh, power where wired).
Reconstructed Internal totals and per-slot kWh from positive deltas and optional recorder replay.
Estimated Model-based solar and other best-effort paths without a direct meter.
